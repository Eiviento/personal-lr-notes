# 5.6 链路层加密

## 一、加密位置

链路层加密，对上层 L2CAP→ATT→GATT 完全透明。上层只管收发，链路层自动加解密。

## 二、AES-CCM

同时提供加密和完整性校验：
- **CTR（Counter Mode）**：加密（明文→密文）
- **CBC-MAC**：生成 MIC（4字节防篡改标签）

接收方：CRC校验 → AES-CTR解密 → MIC比对。MIC 不匹配 = 数据被篡改或密钥不对 → 丢弃。

## 三、Session Key 派生

LTK 不直接用于加密，而是派生 Session Key：
```
Session Key = AES-CMAC(Key=LTK, Data=SKDm||SKDs)
```

每次连接 SKDm/SKDs 是全新随机数 → Session Key 每次都不同 → 防重放攻击。

## 四、加密三次握手

```
LL_ENC_REQ (SKDm, IVm, Rand, EDIV)
LL_ENC_RSP (SKDs, IVs)
LL_START_ENC_REQ ← 明文！此后所有包加密
LL_START_ENC_RSP
═════ 后续全部加密 ═════
```

LL_START_ENC_REQ 本身明文（对方需先读到"开始加密"才能切换模式）。

## 五、加密范围

| 字段 | 加密？ |
|------|-------|
| Header（LLID/SN/NESN/MD/Length）| ❌ 明文（链路层必须先解析） |
| Payload（L2CAP+ATT 数据）| ✅ 密文 |
| MIC | ✅ 密文 |
| CRC | ❌ 明文（物理层误码检测） |

## 六、对开发的影响

- 加密透明，App 不控制开关
- Insufficient Encryption 错误 = 链路未加密 → 检查绑定状态
- MIC 失败 = 密钥不匹配 → `removeBond()` 重新配对
- LL_ENC_REQ/RSP 在 HCI Snoop Log 中可见
- 空包在加密状态下也会加密

## 问答记录

### Q1：不管是否经过确认，两个设备之间传输的数据都是经过加密的吗？

**分情况：**

| 场景 | 加密了？ | 密钥有多强？ | 能防被动窃听？ | 能防主动 MITM？ |
|------|---------|-------------|--------------|----------------|
| SC + Numeric Comparison | ✅ | 128-bit | ✅ | ✅ |
| SC + Just Works | ✅ | 128-bit | ✅ | ❌ **MITM 能解密** |
| Legacy + Passkey | ✅ | ~20-bit | ⚠️ 可暴力破解 | ⚠️ |
| Legacy + Just Works | ✅ | TK=0, 形同虚设 | ❌ 旁听者也能算 STK | ❌ |

**SC Just Works 下的 MITM**：

```
攻击者 M 拦截配对双方的公钥，替换成自己的：
  Phone ↔ M: SessionKey₁ → M 能解密、修改、转发
  M ↔ 耳机:  SessionKey₂ → M 能解密、修改、转发

M 完全透明地读、改、转发所有数据。
加密是真实的(AES-CCM, 128-bit)，但 M 拥有密钥。
```

> **SC Just Works：加密了但不知道跟谁加密。Numeric Comparison：加密了且确认了对方身份。Legacy Just Works：加密了但任何人旁听都能算出来密钥。**

加密和认证是两个独立属性——加密保数据机密性，认证保通信方身份。BLE 的加密(AES-CCM)始终生效，认证取决于配对方式。

### Q2：加密过程涉及广播包吗？

**不涉及。** 加密的整个协商过程（LL_ENC_REQ/RSP → LL_START_ENC_REQ/RSP → AES-CCM 加密通信）全部发生在连接建立之后，走 LL Data PDU。广播包（ADV_IND 等）只在发现和建连阶段使用，31 字节 AdvData 装不下 ECDH 公钥，也没有 L2CAP 信道做 SMP 交互。

### Q3：什么场景用加密？能不能关？

**Q3a：什么场景需要加密？**

加密由 GATT Characteristic 的权限（Permission）控制，不是 App 手动开关。协议栈发现权限不够时自动触发。

| 场景 | 为什么需要加密 | 安全等级 |
|------|---------------|---------|
| 医疗设备（心率/血糖/血氧） | 健康数据受法律保护，明文 = 隐私泄露 | Level 3~4 |
| 支付终端（POS/ATM） | 交易数据明文 = 金融欺诈 | Level 4 |
| 智能门锁/车钥匙 | 开锁指令被重放 = 物理安全失守 | Level 4 |
| 固件 OTA 升级 | 固件被篡改 = 设备变砖/成肉鸡 | Level 3~4 |
| 工业传感器（流量计等） | 计量数据被篡改 = 计量欺诈 | Level 2~3 |
| 个人设备（手表/手环/TWS） | 消息内容泄露 = 隐私侵犯 | Level 2~3 |
| HID 键盘 | 输入凭证明文 = 密码泄露 | Level 3+ |

触发流程——并非 App 手动调加密，而是协议栈自动拦截：

```
App: readCharacteristic(handle=0x0015)
  → GATT 查权限: 需要 "Encryption Required"
  → 当前链路未加密
  → 协议栈自动:
      如果绑定过 → 直接用 LTK 启动加密（用户无感）
      如果首次连 → 弹出配对对话框 → 用户确认 → 加密
  → 加密完成后 → 自动执行原来的 readCharacteristic
```

> **触发加密的不是 App，是 GATT 权限。App 正常读写，协议栈发现权限不够时自动拦截、加密、然后重放。**

**Q3b：开了加密后，简单数据也加密吗？**

**是的，无一例外。** 加密是链路层总开关——LL_START_ENC_RSP 之后，这条连接上所有包的 Payload + MIC 全部 AES-CCM 加密：

- ATT Write Request（写敏感数据）→ 加密 ✓
- ATT Notification（通知）→ 加密 ✓
- ATT Read Request（读公开设备名）→ 加密 ✓ ← 即使是公开信息
- **空包（心跳/ACK，Payload=0）→ 也加密 ✓** ← 空包也带 MIC！
- LL Control PDU（参数更新等）→ 不加密（始终明文）

**为什么空包也要加密？** 空包的 Payload 长度为 0，但 MIC 仍然存在——如果某个包不带 MIC，攻击者就可以在加密流中插入伪造的空包来扰乱 SN/NESN 序列号，导致连接断开（DoS）。

**Q3c：有停止加密的命令吗？**

**有暂停，没有永久停止。**

BLE 4.2 引入了 `LL_PAUSE_ENC_REQ`(Opcode=0x0A) / `LL_PAUSE_ENC_RSP`(Opcode=0x0B)，但设计目的是**换钥匙**，不是**关掉省电**：

```
═══ 旧 LTK 加密 ═══
      │
      ├── LL_PAUSE_ENC_REQ/RSP    ← 暂停，回到明文
      │
      ├── SMP: 重新配对，生成新 LTK
      │
      ├── LL_ENC_REQ/RSP          ← 用新 LTK 派生新 SessionKey
      ├── LL_START_ENC_REQ/RSP    ← 恢复，用新密钥加密
      │
  ═══ 新 LTK 加密 ═══
```

典型场景：
- **安全升级**：连接中从 Legacy Pairing 升级到 LE Secure Connections
- **密钥轮换**：长连接（数小时/数天）定期换密钥，降低单密钥暴露风险
- **权限降级后重加密**：对端换了，需要用新密钥

不存在 `LL_STOP_ENC`。原因：①如果允许单方面关加密，攻击者可以伪造这条命令把加密链路降级为明文；②加密开销接近零（硬件 AES），不存在"为了省电关加密"的需求。

**退出加密的唯一方式：断开连接。**

```
加密连接 → LL_TERMINATE_IND → 断开
         → 重新 CONNECT_IND → 明文链路
```

**但：设备重新建连后，如果 App 访问需要加密的 Characteristic，协议栈又会自动触发加密。** 不访问需要加密的属性就不会触发——加密的触发权在 GATT 权限表。

**Q3d：加密生命周期状态机**

```
        连接建立
           │
           ▼
    ┌─────────────┐
    │   未加密     │ ← 刚建连，所有包明文
    │  (Plaintext) │
    └──────┬──────┘
           │ SMP 配对 → 算出 LTK
           │ LL_ENC_REQ/RSP → 派生 SessionKey
           │ LL_START_ENC_REQ/RSP
           ▼
    ┌─────────────┐
    │   已加密     │ ← 此后所有 Data PDU 加密
    │  (Encrypted) │
    └──────┬──────┘
           │ LL_PAUSE_ENC_REQ/RSP  ← 唯一"暂停"入口
           ▼
    ┌─────────────┐
    │    暂停      │ ← 明文状态，仅用于密钥更新
    │  (Paused)    │    暂停期间不能发 GATT 数据
    └──────┬──────┘
           │ LL_START_ENC_REQ/RSP  ← 必须恢复
           ▼
    ┌─────────────┐
    │   已加密     │ ← 用新密钥
    │  (Encrypted) │
    └─────────────┘

退出加密的唯一方式：断开连接（LL_TERMINATE_IND）
```

> **加密是单向门——进去了就出不来，除非断连或者暂停换钥匙。暂停也只能"暂停→恢复"，不能"暂停→就这样明文跑下去"。**
