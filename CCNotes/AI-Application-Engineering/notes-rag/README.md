# notes-rag · RAG 原理讲义

> 能看懂 `src\rag\` 的代码，但不确定「**向量化 / 检索 / 融合**」到底在干什么？
> 这份讲义把它们从 **直觉 → 公式 → 真实输出** 讲一遍，每个原理都配一个能亲手跑的实验。

## 怎么用

1. **打开 `index.html`**（双击即可）——单文件、零外部依赖、可离线阅读，也支持深色主题。
2. **跑实验**（可选，但强烈建议）：`examples\` 下 4 个脚本，每个讲一个点，跑起来就有输出。

```bash
PYTHONIOENCODING=utf-8 "E:\software\OfficeWorkLife\Anaconda\envs\agent_env\python.exe" notes-rag\examples\e1_vector_basics.py
```

## 文件清单

| 文件 | 讲什么 |
|------|--------|
| `index.html` | 讲义主体：① 向量化 ② 检索 ③ 融合 ④ 串回代码 |
| `examples\e1_vector_basics.py` | 3 维玩具向量——手算余弦，看清「相似度 = 夹角余弦」 |
| `examples\e2_embedding_real.py` | 真实 BGE 模型（512 维）——看真实语义相似度长什么样 |
| `examples\e3_retrieval.py` | 向量路 vs BM25 路对照，外加「直接相加会怎样」的演示 |
| `examples\e4_fusion_rrf.py` | RRF 融合——手算 vs 项目代码逐项核对（exit 0 = 完全一致） |
| `data\sample_docs.md` | 6 段小语料（**故意做小**，好让你一眼看完全部内容） |

## 建议顺序

`e1` → `e2`（向量化）→ `e3`（检索）→ `e4`（融合）。

两种读法都行：顺着讲义读、遇到实验就跑去对照；或者反过来「先把脚本跑一遍看输出，再读讲义解释为什么」。

## 一条本目录的约定

**讲义里出现的每一个数字，都来自 `examples\` 的真实输出**，不是手编的。

核实方法很简单——把脚本跑一遍，跟讲义里的数字对。`e4` 更进一步：它把「手算结果」和「项目代码结果」并排打印并逐项核对，**只有两者一致脚本才 exit 0**。

## 与项目的关系

- 本目录**只解释原理，不改动 `src\rag\` 任何代码**——靠 `import` 复用真实实现，所以讲义讲的就是项目真在跑的东西。
- 想跑通**完整 RAG（检索 + 生成）**：用 `scripts\ask_local.py`（一条命令，无需起服务）。
- 配套的另一套讲义 `notes-web\` 讲的是**阶段 1 的实现过程**（四课）；本目录讲的是**原理**。两者互补。
