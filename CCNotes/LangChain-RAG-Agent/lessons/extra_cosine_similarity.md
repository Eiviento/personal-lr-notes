## 一、三个零件

### 1. 向量 = 一串数字 = 空间里的一个箭头

```
  最简单的向量就是**一串数字**，比如 a = [3, 4]。

        y
        ↑
      4 ┤        ╱ (3, 4)   ← 箭头尖在这里
        │      ╱
        │    ╱
        │  ╱
        └──┴──────────→ x
        0  3
```

第一个数是 x 方向走多远，第二个数是 y 方向走多远。**两个数就确定了这个箭头。**

到了 AI 里向量是同一个东西，只是数字变多：

| 数字个数 | 是什么 |
|---------|--------|
| 2 个 | 平面上的箭头（本课用这个，好在纸上画） |
| 512 个 | 512 维空间的箭头（**项目里 BGE 的输出**） |
| 1536 个 | OpenAI embedding 的维度 |

512 维画不出来，但**所有规则和 2 维一模一样**。先在小维度搞懂，再相信它在高维也成立——这就是本课全程用 `[3, 4]` 的原因。

**文本怎么变成向量？** embedding 模型干的就是这件事：一句话 → 一串数字。意思相近的两句话 → 两个箭头指向相近的方向。（模型内部三步见 `phase4_rag.md`）

### 2. 点积 = 对应位置相乘再相加

```
      a·b = 3×6  +  4×8
          = 18   +  32
          = 50
```

三个数、五个数、512 个数都是这个套路——**就是乘加，没有任何玄机**。项目里 numpy 的写法是 `a @ b`。

### 3. 模长 = 箭头有多长（勾股定理的推广）

`[3, 4]` 正好构成 3-4-5 直角三角形：

```
      |a| = √(3² + 4²) = √25 = 5
      n 维：|a| = √(x₁² + x₂² + ... + xₙ²)
```

> ★ **模长和方向是两件独立的事**——第 4 节会拿这个做文章。

## 二、余弦相似度是什么：只看方向，不看长短

两个箭头之间有个**夹角 θ**。余弦相似度就是去算这个角的余弦值 cos θ：

```
                  a·b           点积
      cos θ = ───────────  =  ──────────────
               |a| × |b|       模长 × 模长
```

> ★ **关键理解**：分子是点积，分母是"两边长度相乘"。**分母的作用是把长度因素除掉**，让结果只剩下"方向对不对"。

几何意义（高中知识复习）：

| cos 值 | 夹角 | 意思 |
|--------|------|------|
| `1` | 0° | 两个箭头完全同向 → **最相似** |
| `0` | 90° | 两个箭头垂直 → **毫无关系** |
| `-1` | 180° | 两个箭头完全反向 → **最不相似** |

### 手算验证（实测输出）

```
  都以 a = [3, 4] 为基准（|a| = 5.0）：

  完全同向 b = [6, 8]   点积=  50  模长=5×10  cos = 50/(5×10) =   1.00   应得 1
  垂直     b = [4, -3]  点积=   0  模长=5×5   cos = 0/(5×5)  =   0.00   应得 0
  完全反向 b = [-3, -4] 点积= -25  模长=5×5   cos = -25/(5×5) = -1.00   应得 -1
```

看"垂直"那行：点积是 0 → 余弦也是 0 → 两句话毫无关系。**这就是为什么向量检索能工作：方向对了，分数就高。**

> ★ **一个真实细节**：embedding 出的向量里，余弦**很少是负数**。因为语义空间里"完全相反的意思"基本不存在——"水表"和"不是水表"在向量空间里方向其实很接近（都围绕"水表"这个词）。实际能见到的范围大致是 `0.3 ~ 1.0`。

## 三、那个等式是怎么来的

### 先说什么叫归一化（normalize）

**把一个向量除以它自己的模长：**

```
      â = a / |a|        （上加小帽子表示"处理过的 a"）
```

效果：新向量的模长**必然等于 1**（方向不变，长度拉到 1）：

```
      验证：|â| = |a / |a|| = |a| / |a| = 1
```

这种长度恰好为 1 的向量叫**单位向量**。

### 再看余弦的公式会发生什么

把公式里的 a、b 都换成归一化后的 â、b̂：

```
      cos θ = (â · b̂) / (|â| × |b̂|)
```

既然 `|â| = |b̂| = 1`，分母就是 `1 × 1 = 1`：

```
      cos θ = (â · b̂) / 1 = â · b̂
```

> ★ **这就是那句话的全部来历：归一化之后，两个向量的点积就是余弦相似度。** 因为余弦公式的分母被归一化变成了 1，除了个寂寞。

### 为什么大家喜欢这个结论

余弦相似度要算 **1 次点积 + 2 次开根号**（开根号慢）。归一化之后只要 **1 次点积**。向量库动辄比几百万次，省掉两次开根号是实打实的性能收益。

所以工程上的标准做法是：**入库前就归一化好**，检索时只用算点积。`phase4_1_rag.py:133` 干的就是这件事。

### 实测验证（512 维随机向量）

```
                  点积            余弦         归一化后点积与余弦之差
    1     -15.818163     -0.031933      6.94e-18
    2      25.492972      0.047944      2.08e-17
    3     -51.469123     -0.097548      1.39e-17
    4      12.855466      0.026640      0.00e+00
    5      -9.798179     -0.019032      2.08e-17
```

最后一列是 0 或者 `1e-17` 这种级别——那是**浮点数的舍入误差**，不是算法差异。

> **"相等"在数学上成立，在计算机里差个 1e-17，可以忽略。**

## 四、为什么要归一化：点积会被"长度"带偏（本课重点）

前面说过：**方向和长度是两件独立的事**。现在看这个区别有多大威力。

造三个向量，**方向完全一样**，只是长度不同：

```
      a  = [3, 4]                       ← |a| = 5
      b  = [6, 8]                       ← 就是 a 的 2 倍，|b| = 10
      c  = [300, 400]                   ← 就是 a 的 100 倍，|c| = 500

  对比                        点积        余弦   说明
  a vs b (2倍)               50    1.0000   ← 点积变了，余弦没变
  a vs c (100倍)           2500    1.0000   ← 点积变了，余弦没变
```

**它们指向完全相同的方向，相似度理应完全一样。但：**

- **点积从 50 涨到 2500**（差 50 倍！）——它被"长度"污染了
- **余弦始终是 1.0** ——因为分母把长度约掉了，只剩方向

### 这会怎么害你

设想你是个检索系统，用点积给文档打分：

```
      文档A：和查询很相关，但向量长度是 5    → 点积 50
      文档B：和查询不太相关，但向量长度 500  → 点积可能 500
```

结果 **文档B 排在前面**。系统选错了，而且错得莫名其妙——看起来打分还很高。

> ★ **这就是归一化的全部意义：先把长度统一成 1，让分数只反映方向。**
>
> **一句话记忆：不归一化的点积 = 方向分 × 长度分；归一化把它变成纯方向分。**

### 真实数据：BGE 原始向量的模长确实各不相同

从项目的 BGE 模型里取**未归一化**的原始向量（CLS 池化那一步）：

```
  文本                    原始模长        归一化后模长
  设备位置通过水表阀门上报        6.5552        1.0000
  水表阀门模板协议            7.6488        1.0000
  环境监测数据上传            6.8897        1.0000

  同一对文本，两种算法的结果：
    原始向量  点积 =  33.9373      余弦 =   0.6769   ← 差很远
    归一化后  点积 =   0.6769      余弦 =   0.6769   ← 一致了
```

三个原始模长 **6.5552 / 7.6488 / 6.8897 —— 各不相同**。这就是为什么模型输出后必须补一步归一化。

> ★ **诚实说明**：本例里按点积排序和按余弦排序**碰巧结果一样**，因为这两句的模长（6.55 vs 7.65）差别还不算大。但数值尺度完全不同（33.94 vs 0.68）——只要文档一多、长短差距一大，排序就会翻车。**归一化是为了消除这个隐患，不是修一个已经出现的 bug。**

## 五、回到项目代码：`phase4_1_rag.py:133`

现在回头看 embedding 函数的第三步，每个字都该看得懂了：

```python
hidden = outs[0][0]                          # [seq, dim] 每个 token 一个向量
if self.pooling == "cls":
    pooled = hidden[0]                       # BGE：取 [CLS] 向量
else:
    pooled = (hidden * mask[:, None]).sum(0) / mask.sum()   # MiniLM：平均池化
pooled = pooled / np.linalg.norm(pooled)     # ← 第 133 行：归一化
#        └──────┘   └───────────────┘
#          向量       它自己的模长
#                                  结果：模长变成 1
```

代码里那行注释只写了四个字「归一化 → 余弦相似度」，本课讲的就是这四个字背后的推理：

```
      余弦公式 = 点积 / (模长×模长)
          ↓ 归一化把每个模长变成 1
          ↓ 分母 = 1×1 = 1
      余弦 = 点积      ← 注释说的就是这句
```

配套的另一处（第 146-147 行，建向量库时）：

```python
get_or_create_collection(
    ...,
    embedding_function=LocalBertEmbedding(MODEL_DIR, pooling="cls"),
    metadata={"hnsw:space": "cosine"},     # ← 告诉 chroma：用余弦度量
)
```

> ★ 这两处是**配套**的：embedding 函数把向量归一化好，向量库声明用 cosine 距离。因为向量已经是单位长度，chroma 内部算 cosine 或算点积，结果完全一样。

## 六、速记表

| 概念 | 公式 / 值 | 一句话 |
|------|----------|--------|
| 向量 | 一串数字 | 空间里的箭头，512 维和 2 维规则一样 |
| 点积 | `Σ xᵢyᵢ` | 对应位置相乘再相加 |
| 模长 | `√(Σ xᵢ²)` | 箭头多长，勾股定理推广 |
| 余弦相似度 | `点积 ÷ (模长×模长)` | 分母除掉长度，**只看方向** |
| cos = 1 / 0 / -1 | 同向 / 垂直 / 反向 | 最相似 / 无关 / 最不相似 |
| 归一化 | `a / |a|` | 把模长变成 1，方向不变 |
| **归一化后** | **点积 == 余弦** | 因为分母变成 `1×1 = 1` |
| 为什么要归一化 | 防长度污染 | 不归一化时点积 = 方向分 × 长度分，长向量拿虚高分 |

**一句话记忆：余弦相似度 = 除掉长度只看方向的点积；归一化把"除掉长度"这一步提前做掉，于是点积本身就等于余弦了。**
